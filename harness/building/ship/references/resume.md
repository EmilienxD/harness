# Resume a PR

1. Resolve the PR and read its body, reviews, review threads (including inline comments), issue comments, base/head branches, and mentioning issue. Paginate API results as needed. Use `Refs #n` and GitHub cross-references to find the issue; ask only if the intended issue is ambiguous. Preserve its claim. Read project target/merge instructions and account for requested review changes in the next report.
2. Locate the branch with `git worktree list --porcelain` and reuse its initialized worktree. If missing, recreate it only through the project's worktree script. Locate the external run record and original stub/workflow anchor from branch history. Do not manufacture a new initial commit on the existing branch or reset its work. If the original contract/session cannot be recovered, establish the uncertainty with the user while preserving the PR.
3. Run `harness loop lookup <recorded-session>`. Reuse that session only when it still exists and its last recorded context percentage is below `loop.freshContextPercent`; for unknown usage, skip the context rule and apply the remaining freshness/quality/cap rules. An implementer waiting on a live Stop receives feedback with the evaluated token. A released session uses `harness loop resume <session> --file <feedback>`; Aboard reuses its terminal, while standalone resume requires the old terminal to have closed. If it cannot resume, release any active wait and launch a fresh implementer within the cap. A working or taken-over session is paused for its next successful Stop; stale feedback is never forced through.
4. Supply review context by path alongside the original context, branch diff, last report, and cumulative problems. Keep orchestration metadata out of the implementer's inputs. The Lead owns any clarified workflow or stub criteria; make authorized changes explicit and retain their history. Judge new reports through the same rules and repeat the closeout gates, including the one target sync and confirming round when it brings changes.
5. Update the existing PR and issue comment. Mark a passing draft ready with `gh pr ready`; apply the issue's auto-merge decision or leave it open. The issue remains open. Preserve a failing resumption as a draft with `[AI]-needs-decision` and a precise question.
